## Two model findings found in passing — record, do not fix

- **Finding 11 (new): a cash shortfall is invented.** `lbo_engine/debt_model.py`
  step 7 sets `ending_cash = minimum_cash + unswept` unconditionally, so with
  negative levered FCF, or when mandatory repayments exceed cash in hand, the
  cash balance is restored out of nothing. The default deal hits this in year 5,

  shrink, so `min(amount, beg) == beg`), so that one is safe inside 2.4.

## 1. The tranche specification — `core/debt.py` (new)

The input-facing spec, in wizard units (percentages as numbers like `6.5`,
money in the deal's unit), the nine type presets, and the builder that turns
specs into engine `Tranche` objects. **The engine stays dumb about market
conventions**: `core/debt.py` resolves a floating tranche into an all-in rate
per year and hands `lbo_engine` a plain `rate_path`. That is what lets PLAN.md
4.2 drop market data in without touching `lbo_engine/`.

```python
TRANCHE_TYPES = ("amortising_term_loan", "institutional_term_loan", "unitranche",
                 "second_lien", "senior_notes", "pik_notes", "vendor_loan",
                 "revolver", "shareholder_loan")
REFERENCE_RATES = ("SOFR", "SONIA", "ESTR", "EURIBOR", "TONA", "SARON",
                   "BBSY", "MIBOR", "custom")

@dataclass(frozen=True)
class TrancheSpec:
    name: str                      # user text; a dict key in the debt schedule
    kind: str                      # one of TRANCHE_TYPES
    amount: float = 0.0            # money, the deal's unit; DRAWN at close
    commitment: Optional[float] = None   # revolver limit; None = amount
    floating: bool = False
    fixed_rate: float = 0.0        # %, used when floating is False
    reference_rate: str = "custom" # label, and which curve 4.2 fills in
    reference_level: float = 0.0   # %, the flat path when reference_path is empty
    reference_path: tuple = ()     # % a year, forward-filled past its end
    margin: float = 0.0            # %
    floor: float = 0.0             # %, on the reference only
    maturity_years: int = 7
    amort_pct: float = 0.0         # % of original principal a year
    amort_schedule: tuple = ()     # money a year; overrides amort_pct when given
    upfront_fee_pct: float = 0.0   # % of amount, a use of funds at close
    commitment_fee_pct: float = 0.0  # % of the undrawn commitment, a year
    sweep: bool = False
    sweep_share: float = 100.0     # % of the available sweep this tranche may take
    pik_share: float = 0.0         # % of the interest capitalised
    drawn_pct: float = 100.0       # % of the commitment drawn at close
    allow_redraw: bool = False     # a revolver funds a cash shortfall
    currency: str = ""             # "" = the deal's; carried, never calculated with
```

`__post_init__` refuses an unknown `kind` or `reference_rate` (the tests expect
`ValueError` naming the field).

Functions in the same file: `PRESETS` (per type), `spec_from_kind`,
`rate_in_year(spec, year)`, `to_tranche(spec, hold, priority)`,
`build_capital_structure(specs, ebitda, hold)` (de-duplicates names
deterministically, sets `sweep_priority = index + 1`),
`financing_fees(specs) -> Optional[float]`, `equivalent_tranches(deal, cfg)`
(today's senior + mezzanine written out explicitly — the exactness test's
subject), `sim_tranches(specs, hold)` for the vectorised path, and
`check_specs(...)` raising when sponsor equity would be negative (the old
`debt_pct <= 99` bound no longer guards it).

### The nine types: presets vs real behaviour

| Type | Preset | New behaviour |
|---|---|---|
| Amortising term loan (TLA) | floating, amort 5%/yr, sweep, maturity 6 | none |
| Institutional term loan (TLB) | floating, amort 1%/yr, sweep, maturity 7 | none |
| Unitranche | floating, bullet, one blended margin, sweep, maturity 7 | **none** — that is the point: one instrument replacing senior + mezzanine |
| Second lien | floating, bullet, no sweep, maturity 8 | ordering only |
| Senior notes / HY | **fixed**, bullet, no sweep, maturity 8 | none |
| PIK notes | fixed, bullet, `pik_share=100`, no sweep, maturity 8 | **PIK accrual** |
| Vendor loan | fixed, bullet, `pik_share=100`, no sweep, maturity 8 | reuses PIK accrual |
| Revolving credit facility | floating, `commitment` set, `commitment_fee_pct=0.5`, sweep, `allow_redraw`, maturity 6 | **commitment vs drawn, commitment fee, redraw** |
| Shareholder loan | fixed, bullet, `pik_share=100`, no sweep, maturity 10 | reuses PIK accrual |

So exactly three mechanics are new — **PIK accrual**, **the revolver** and
**the sweep share**. Everything else is preset data over fields the engine
already has.

- **Revolver.** `amount` is the balance drawn at close and is a source of funds
  like any other tranche; `commitment` is the limit and never a source.
  Interest is charged on the drawn balance only. The commitment fee each year is
  `(commitment - beginning drawn) * commitment_fee_pct`, an ongoing cash cost,
  so it belongs in interest expense (it gets the tax shield), **not** in entry
  costs. `allow_redraw`: at step 7, when `cash_in_hand < minimum_cash`, draw
  `min(minimum_cash - cash_in_hand, commitment - balance)` onto the balance
  instead of inventing cash (finding 11).
- **PIK accrual.** `interest = balance * rate` as today;
  `pik = interest * pik_share`; `cash_interest = interest - pik`;
  `ending = beginning - mandatory - sweep + pik`. The income statement expenses
  the **full** interest (deductibility caps are 2.5); the cash flow model adds
  the accrued part back as non-cash. Net debt at exit therefore includes the
  accrual, and the bullet at maturity repays beginning balance plus that year's
  accrual.

## 2. The rate rule

```python
def rate_in_year(spec, year):            # year is 1-indexed, returns a decimal
    if not spec.floating:
        return spec.fixed_rate / 100
    path = spec.reference_path or (spec.reference_level,)
    ref = path[min(year, len(path)) - 1] / 100     # forward-fill past the end
    return max(ref, spec.floor / 100) + spec.margin / 100
```

- The **floor applies to the reference only, before the margin** — market
  convention, and what the task asks for.
- A **path shorter than the hold forward-fills its last year**. This matters
  because `lbo_engine/model.py` step 8 reruns the whole model at holds 3-7, so
  a five-year path has to answer for years 6 and 7. Never extrapolate a trend:
  the sensitivity grid must not depend on an invented curve. Say so on screen
  ("years after {n} repeat the last rate").
- A longer path than the hold: the extra entries are ignored, no error.
- `to_tranche()` materialises `rate_path = tuple(rate_in_year(spec, y) for y in
  1..hold)`, so the engine never sees a floor, a margin or a reference name.

## 4. Monte Carlo: keep the two-bucket path, add a tranche path beside it

**Do not generalise `_run_vectorized_core` to K tranches.** The two-bucket loop
has four quirks the deterministic engine does not share (the mezzanine bullet
repays in full at `t == n_yr - 1` whatever its maturity; senior amort has no
schedule object; there is no rounding at all; the cash balance is hard-reset to
`minimum_cash`). A rewrite reproducing all four is possible, but per C2 nothing
in the suite would catch a divergence, and the blast radius is every user's
simulation plus `jobs/drill.py`'s pinned summary. So: `if not p.tranches:`
today's code, untouched; otherwise a new `_debt_loop_tranches(...)`. Two debt
loops in one file is honest and temporary — a later task can unify them once MC
output is pinned.

`SimulationParams` gains one field, `tranches: list = field(default_factory=list)`
(flat records from `core.debt.sim_tranches`), which breaks
`test_simulation_params_match_streamlit` per C1 → the same allow-list
treatment, asserting the golden value is `[]`.

The rate shock, per path: `shock = draws["interest"] - p.interest_mean`; for a
floating tranche `rate_t = np.maximum(ref[t] + shock, floor) + margin`, i.e.
**floored after the shock, before the margin**, so a path drawing the reference
negative against a 0% floor pays `floor + margin`. Fixed tranches are
untouched, so an all-fixed structure gives the `Interest` driver a Spearman rho
near zero — correct but surprising, so test it and show a rail note on the
Monte Carlo screen when no tranche is floating.

`core/montecarlo.py`: `build_sim_params` passes
`tranches=sim_tranches(deal.tranches, int(mc.hold))`, and
**`growth_exit_heatmap` must pass `capital_structure=...` into its
`LBOParams`** or the heatmap silently reverts to the percentage structure —
exactly the class of bug finding 3 was.

## 5. Per-tranche fees vs `financing_fees_pct` — no double counting

`Tranche.fee_pct` and `CapitalStructure.total_fees` exist but `run_lbo` never
reads them, so per-tranche upfront fees are genuinely new money. Rule: **the
flat settings fee (`fin_fee_pct`, 2.6%) applies unless a tranche sets its own
upfront fee.**

```python
def financing_fees(specs) -> Optional[float]:
    if not any(s.upfront_fee_pct for s in specs):
        return None          # the settings' flat % of total debt stands
    return sum(s.amount * s.upfront_fee_pct / 100 for s in specs)
```

`None` → `financing_fees_amount=None` → the existing expression runs →
bit-identical. This sentinel matters for the exactness test: `420*0.026 +
180*0.026` and `600*0.026` differ by an ulp, so seeding per-tranche fees from
the setting would **not** be bit-identical. Never seed `upfront_fee_pct` from
`fin_fee_pct` when creating a tranche. Upfront fees are a use of funds at close
(entry costs, the bridge's "Fees at entry"); commitment fees are ongoing and
belong in interest expense. The UI states which rule is in force, so the switch
is never silent.
