# Plan — PLAN.md 2.4b: the simulation and the screen

**2.4a is done and merged into this branch**: the model takes debt structures
of any shape (`core/debt.py`, the engine's tranche mechanics, the API, storage
and the tests). What follows is what is left. Delete this file in the PR that
finishes 2.4b.

## What 2.4a already settled

- `core/debt.py` owns the market conventions: `TrancheSpec`, the nine kinds as
  `PRESETS`, `rate_in_year` (`max(reference, floor) + margin`, the path
  repeating its last year), `build_capital_structure`, `equivalent_tranches`,
  `financing_fees`, `check_specs`, `summary`.
- `lbo_engine` gained PIK accrual, the sweep share, the commitment fee and the
  revolver redraw, each defaulting to an exact no-op. A repayment at maturity
  settles the year's accrual as well as the principal.
- `tests/golden_compare.py::assert_close` takes `extra`; `TRANCHE_FIELDS` in
  `tests/test_core_parity.py` names the nine new output fields, and a test
  shows each adds nothing for the recorded deals. **`tests/golden/golden.json`
  is untouched and must stay that way.**
- `api/main.py` turns a refusal into a 422 without logging it, and strips the
  echoed input from every validation error.
- `db/deals.py::OMIT_WHEN_DEFAULT` (renamed from `LABEL_DEFAULTS`) keeps the
  tranche list out of deals that do not have one.
- **The simulation refuses a deal that lists tranches**
  (`core.montecarlo.TranchesNotSimulatedYet`, 422). That refusal is 2.4b's
  job to remove — it is what stops the simulation quietly financing a deal
  differently from the screen in the meantime.

## 2.4b, in order

1. **Pin the simulation's output first.** Nothing pins it today: only
   `sim_params` is in the golden file, and `tests/test_api.py` checks
   reproducibility for a seed. Write `tests/test_montecarlo_baseline.py`
   pinning `run_vectorized_simulation_full` for `seed=42`, n=20,000, default
   params — mean IRR, p5, p95, wipeout rate — to 1e-12, and mutation-check it
   (`senior_rate = interest * 1.001` must fail it). Everything after this
   depends on it.

2. **A tranche path beside the two-bucket one**, not a rewrite.
   `_run_vectorized_core` keeps its body under `if not p.tranches:`. The
   existing loop has four quirks the deterministic engine does not share (the
   mezzanine bullet repays in full at `t == n_yr - 1` whatever its maturity;
   senior amort has no schedule object; there is no rounding at all; the cash
   balance is hard-reset to `minimum_cash`), and with nothing pinning the
   output before step 1, a rewrite could change every user's simulation
   silently. `SimulationParams` gains one field, `tranches`, which breaks
   `test_simulation_params_match_streamlit` on the key set — same `extra=`
   treatment as 2.4a, asserting the golden value is `[]`.

3. **The rate draw moves floating facilities only.**
   `shock = draws["interest"] - p.interest_mean`; per floating tranche
   `rate_t = np.maximum(ref[t] + shock, floor) + margin` — floored **after**
   the shock, before the margin, so a path drawing the reference negative
   against a 0% floor pays `floor + margin`. Fixed tranches are untouched, so
   an all-fixed structure gives the `Interest` driver a Spearman rho near
   zero. That is correct but surprising: test it, and say so on the Monte
   Carlo rail when no facility is floating. Add the PIK add-back to the
   simulated cash flow the same way (`+ non_cash[:, t]`, all zeros in the
   default path, so it is an exact no-op).

4. **`growth_exit_heatmap` must pass `capital_structure=`** into its
   `LBOParams`, or the heatmap silently reverts to the percentage structure —
   the same shape of bug as model finding 3. Test it: a tranche edit must move
   the grid.

5. **Remove the `TranchesNotSimulatedYet` refusal** once 2, 3 and 4 are in,
   and delete its test.

6. **The Debt step's editor.** Rail, replacing the `groupCapital` group:
   - **No tranches:** today's four fields plus a "Use explicit tranches"
     button calling `setFields({ tranches: equivalentTranches(inputs, settings) })`
     — a helper in `web/src/lib/deal/capital.ts` mirroring
     `core.debt.equivalent_tranches`. **The first click must not move a single
     number on the deal's own result**; the exit-sensitivity grid's *other*
     hold columns do change, because an explicit facility's maturity does not
     stretch with the hold (CLAUDE.md finding 11) — say so in the UI.
   - **With tranches:** a `TrancheList` in the same `RailGroup`, one row per
     facility, hairline-separated (`border-b border-line`), never a card. A
     row is a button (`name · kind · fmtMoney(amount)`) expanding into
     `NumberField`s (`unit: MONEY` for amount so `useMoney()` labels it, `%`
     for rates, fees and shares, `yr` for maturity) and two `<select>`s in
     `MoneySelects`'s `SELECT` class. Remove, and up/down which rewrite the
     order (first in the list is swept first). Logical CSS throughout
     (`ps`/`pe`, `border-s`/`-e`, `text-start`) for right to left.
   - The rate path is a row of per-year `NumberField`s labelled with
     `useFiscalLabels().deal(...)`, plus a note that later years repeat the
     last rate.
   - **Results:** a `span={6}` "Capital structure" tile above the per-tranche
     schedules, from `DealRunResponse.capital_structure`. The existing tiles
     loop `res.tranches`, so new facilities appear for free; add `Cash
     interest`, `PIK accrued` and `Commitment fee` rows **only when
     non-zero**, the way `bridge_steps` hides the fee step, so today's tables
     are unchanged.
   - `web/src/lib/deal/fields.ts`: `DEFAULT_INPUTS.tranches = []`, `apiInputs()`
     omits it when empty (mirroring `OMIT_WHEN_DEFAULT`), and `changedKeys`
     needs a deep compare for the array or the changes bar will miss edits.
     `setMoney` must convert each tranche's amount when the unit changes, or
     the deal changes size.

7. **Text.** Every word into `web/messages/en.json`: a `trancheKinds`
   namespace for the nine names (with an `i18n-keys: trancheKinds.*` comment),
   `fields.tranche_*` for the field labels, `deal.addTranche` /

## Carried forward from the 2.4a reviews — not 2.4b's job

Each was judged out of scope for 2.4 and is recorded rather than fixed. The
first two are pre-existing and only amplified by tranches.

1. **No cap on deals per account, or on saved versions per deal.** Automatic
   checkpoints are bounded (one per 15 minutes, newest 20 kept), but explicit
   saves and new deals are not, and a stored deal with twelve full facilities
   is roughly 20 KB against a few hundred bytes before. A signed-in account
   could fill Neon's free 0.5 GB in about an hour. Wants a per-account deal
   cap, a saved-version cap and a byte budget, checked at the write. Fits
   PLAN.md 1.6's machinery (`api/limits.py`) or 9.2.
2. **`sens_*` settings are unbounded, and `/api/deal/run` has no timeout.**
   `sensitivity_holding_periods` does `list(range(lo, hi + 1))` with no bound,
   and the deal endpoints are not in `RUN_PATHS`, so they get no run limit, no
   slot and no 100 s cap. `sens_hp_max` of 80 takes about 4 s; 200 with 50
   exit steps does not finish. Tranches add about 8% — the exposure is the
   settings. Bound them at the request edge and put the deal endpoints under
   the timeout.
3. **Exception messages still reach the logs and Sentry.**
   `api/observability.py`'s `JsonFormatter` includes `formatException`, whose
   output carries the message, and `scrub_event` clears frame variables but
   not `exception.values[].value`. Both comments claim type-and-traceback
   only. Every path in 2.4 is now a returned 422 rather than a raised error,
   so nothing here leaks today, but the general hardening is worth doing:
   drop the message, keep the type.
4. **`jobs/runner.py` catches only `ValidationError` and `HTTPException`**, so
   a future `deal.run` job kind would turn `UnfinanceableStructure` into a
   logged 500 rather than the 422 the HTTP path gives. Not reachable today
   (the job kinds are the two Monte Carlo ones and the backtest). Fix when a
   deal job kind is added — see CLAUDE.md's gotcha on registering one.
5. **A shareholder loan is treated as debt at exit.** Whether it should join
   the sponsor's proceeds instead is a real modelling decision: ask the user
   or give it its own task.
6. **Cross-currency facilities.** `TrancheSpec` carries `currency` but the API
   does not expose it, and with no FX source every amount is in the deal's
   currency. Revisit after PLAN.md 4.2.
7. **Excel export of the capital structure** — cheap (`api/routers/export.py`
   plus `column_formats`); fold into 2.4b if there is room, otherwise 7.3.
8. **The backtest never sees tranches**: `core/backtesting.py` builds
   `LBOParams` from a plain dict and never touches `DealInputs`. PLAN.md 2.7
   rewrites that screen.
